# Metabrain 2.0 — Groq API Setup

Metabrain, the AI coach, is powered server-side by [Groq](https://console.groq.com) (free tier).
The API key is never exposed to the browser — all requests go through `/api/groq.js`.

## 1. Get a free Groq API key

1. Sign up at https://console.groq.com
2. Go to **API Keys** → **Create API Key**
3. Copy the key (starts with `gsk_...`)

## 2. Add it to Vercel

1. Open your project in the Vercel dashboard
2. Go to **Settings → Environment Variables**
3. Add:
   - **Name**: `GROQ_API_KEY`
   - **Value**: your key from step 1
   - **Environments**: Production, Preview, Development
4. Redeploy for the variable to take effect

For local development, add the same value to a `.env.local` file at the project root:

```
GROQ_API_KEY=gsk_your_key_here
```

## Models used

`api/groq.js` routes requests to two models depending on the `tier` field in the request body:

| Tier   | Model                  | Used for                                              |
|--------|------------------------|--------------------------------------------------------|
| `deep` | `openai/gpt-oss-20b`   | Tasks that benefit from stronger reasoning/structure (e.g. flashcard JSON) |
| `fast` | `llama-3.1-8b-instant` | Main chat coach + lightweight/quick generation tasks   |

Both are cheap on Groq's pay-as-you-go pricing (`llama-3.1-8b-instant` ≈ $0.05/$0.08
per million input/output tokens; `openai/gpt-oss-20b` ≈ $0.075/$0.30) and get much
higher tokens-per-minute headroom than `llama-3.3-70b-versatile` (≈$0.59/$0.79), which
was the previous default for both the main chat coach and flashcard generation and was
the main driver of hitting Groq's TPM limits quickly. The main chat coach now uses the
`fast` tier since it's the highest-volume call in the app; `deep` is kept for tasks
where the extra structure/reasoning of a 20B MoE model helps (currently flashcards).

## AI flashcard generation (`api/flashcards.js`)

Flashcard decks are generated by a dedicated endpoint, `api/flashcards.js`, that also
calls `openai/gpt-oss-20b` on Groq (same model as `deep` coaching tasks) using JSON-mode
responses for reliable parsing. It supports two modes:

- **`notes`** — extracts the highest-yield concepts out of pasted study notes and writes
  an atomic active-recall card for each one.
- **`topic`** — writes a deck from scratch on a named topic, using the model's own
  subject knowledge (no source text required).

Each card comes back with a `front`, `back`, an optional `hint` (memory hook/mnemonic),
a `category`, and a `difficulty`. Uses the same `GROQ_API_KEY` as the coach, with its own
rate limit (300 generations/IP/day) so heavy deck generation can't starve the coach's
chat quota.

The client (`src/lib/aiFlashcards.js`) falls back to the local, fully offline
cloze-deletion generator (`src/lib/clozeGenerator.js`) if this endpoint is unreachable,
unconfigured, or rate-limited — but only for `notes` mode, since `topic` mode has no
source text to fall back on. FSRS (`ts-fsrs`, the open-source spaced-repetition algorithm
Anki uses by default) handles all scheduling downstream of generation and is unaffected
by which engine wrote the cards.

## Branding note

The product-facing name for the coach is **"Metabrain 2.0."** This is fine to keep as your
own product name — you're not required to disclose the underlying model vendor in your UI.
To stay on the safe side of advertising law, avoid claiming you trained/built the model
yourselves; a line like "Metabrain is powered by large language model technology" (already
present in Settings/About) keeps things honest without undercutting the branding.

## Rate limits

`api/groq.js` applies its own conservative in-memory limits (20 requests/minute, 1200
requests/day per IP) to stay comfortably inside Groq's free-tier caps regardless of traffic.
